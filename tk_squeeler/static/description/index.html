TerraKernel Squeeler

Run raw SQL through the Odoo external API, with read-only safety enforced by PostgreSQL.

Built by TerraKernel

Read-only queries

tk.squeeler.execute_read runs one statement in its own READ ONLY transaction, on the replica if one is configured, with a statement timeout and a row cap. PostgreSQL itself rejects any write, DDL or nextval().

Writes, when you need them

tk.squeeler.execute_write runs one statement inside the caller's transaction, in a savepoint, then invalidates the ORM cache. It is gated by its own group.

Query templates

Administrators save vetted read-only queries with typed, named parameters. Integration users run them by code with only one of the template's allowed groups, no raw SQL access needed. describe returns a JSON Schema for the parameters and the result columns.

Full audit log

Every call is recorded with user, query, parameters, row count, duration and error, including denied calls and failed queries.

Works with every Odoo API client

execute_kw (XML-RPC / JSON-RPC), JSON-2 and ODXProxy call_method.

models.execute_kw(db, uid, api_key, 'tk.squeeler', 'execute_read',
                  ["SELECT id, name FROM res_partner WHERE id = %s", [7]],
                  {'limit': 50})

# {"columns": ["id", "name"], "rows": [[7, "Azure Interior"]],
#  "rowcount": 1, "truncated": false}
POST /json/2/tk.squeeler.template/run
{"code": "partner_balance", "params": {"date_to": "2026-09-30", "partner_ids": [7, 9]}}

Pairs with ODXProxy

ODXProxy is a JSON-RPC proxy in front of Odoo, also by TerraKernel. Your apps hold one proxy key instead of Odoo credentials, and reach Squeeler through v1 (execute_kw, any Odoo version) or v2 (JSON-2), with official SDKs for Python, JavaScript/TypeScript, Java/Kotlin, PHP, Swift and .NET. 

from terrakernel.odxproxyclient import ODXProxyClient

with ODXProxyClient(base_url="https://proxy.example.com", api_key="<proxy key>") as client:
    odoo = client.for_instance_v2(url="https://erp.example.com", db="prod", api_key="<odoo key>")
    result = odoo.call_method("tk.squeeler.template", "run", kwargs={
        "code": "partner_balance",
        "params": {"date_to": "2026-09-30"},
    })

Guarantees

  • One statement per call. Smuggled ; COMMIT; ... sequences are rejected before reaching the database.
  • Parameters are always bound by psycopg2, never formatted into the SQL string.
  • Only limit + 1 rows ever leave the database, so the row cap also bounds memory.
  • Template SQL is never returned to API callers, and a missing template looks the same as a forbidden one.
Grant with care. The Read SQL group means database-wide read access, including password hashes, API keys and system parameters. Neither group is given to administrators automatically. Assign them to specific integration users only.

Setup

  1. Install the module. It depends only on base.
  2. Add Squeeler: Read SQL or Squeeler: Write SQL to your integration user.
  3. Optionally create query templates under Settings → Squeeler → Query Templates.
  4. Tune tk_squeeler.max_rows and tk_squeeler.statement_timeout_ms in System Parameters.

The full API reference is in the module's README.md.
